# 薄霧城 · Usugiri Castle

一座虚构的日式山城。原生 HTML、CSS、JavaScript 与 Three.js 构成的静态建筑漫游：从山路、木桥、城门进入主殿，走过茶室、中庭、书斋与兵具间，沿两段木阶抵达望楼。

## 本地运行

在项目目录启动任意静态 HTTP 服务器，例如：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

打开 `http://127.0.0.1:4173/`。ES modules 必须通过 HTTP 加载，不能直接双击 `index.html`。运行网站不需要 Node、npm、打包器、后端或 API key。

## 操作

- 滚动：沿统一的连续相机路线前进、后退。
- 「入城」：抵达木桥；底部章节标记可跳转至各区域。
- 「城内案内」：打开三层平面图，点击空间跳转。
- 「自由观察」：鼠标拖动旋转、滚轮缩放；触屏单指旋转、双指缩放。内部检查自动移除屋顶，返回时恢复。
- 「返回漫游」或 Escape：平滑恢复进入检查前的进度、相机与滚动位置。
- 春、夏、秋、冬：更新植被、地面、环境光、粒子与薄雪，保持相机位置。
- 漫游之后：建筑示意、材料近观、榫卯分解、庭院四季和房间卡片。

## 空间与路线

一单位为一米。前庭地面标高为 4，主殿为 5.2，天守二层为 10.4，望楼为 15.6；主要步行视高为 1.65 米。开场位于较高的山路，沿坡下降到木桥。

主殿呈 U 形围绕露天中庭：西侧茶室、东侧书斋与兵具间、前侧回廊。天守在北侧。两段楼梯的楼板留有真实开口，楼梯平台与楼面连接。

`WAYPOINTS` 中的 `p` 是相机位置，`t` 是观察目标。带 `id` 的点同时供章节标记、平面图和房间卡片使用。`WalkRoute` 以弧长映射滚动进度，避免关键点间距不同造成速度骤变。新增房间时，应一起修改建筑、关键点与平面图。

## 渲染与资源

- 建筑与纹理分批构造，中途让出主线程；先编译并显示主要建筑，再完成外围植被。
- 静态几何按材质合并；重复石块与地板细缝使用实例化。
- 屋顶、季节植被和积雪保持独立，便于剖切与季节更新。
- 阴影缓存；只有季节与剖切变化时更新。远景使用分层山形与雾。
- 中庭池与护城河使用 256/512 像素平面反射；护城河叠加流动的水彩色层和轻微反射扰动。
- 主场景离开视口后停止绘制。材料仅在接近章节时生成高分辨率表面；榫卯 renderer 同样按需初始化，只在进度变化时绘制。
- 默认像素比上限桌面 1.65、窄屏 1.3，可在 `SETTINGS` 中调整。
- 所有配图为本项目三维场景渲染，不使用外部照片。WebP 通过 `loading="lazy"`、`srcset` 和 `sizes` 加载。
- 窄屏庭院为 4:5 裁切，使用 `sizes="225vw"` 估计裁切前宽度，保留纹理清晰度。
- 字体使用系统字体，无外部字体请求。全部运行依赖在 `vendor/`，上线后无需访问 CDN。
- 尊重 `prefers-reduced-motion`，停用环境运动并减少过渡。

## 静态部署

上传 `index.html`、`style.css`、`js/`、`assets/` 和 `vendor/`。保留 `vendor/THREE-LICENSE.txt` 与 `SOURCES.md`。

全部资源使用相对 URL，可部署到域名根路径或 `/repository-name/`。服务器应提供标准 `.js`、`.svg`、`.webp` MIME 类型。没有路由重写要求，推荐对静态资源开启压缩与缓存。

验证仓库子路径的方法：在父目录运行 HTTP 服务，然后访问 `/welldone/`。

## 验收与开发工具

`tests/verify.cjs` 使用 Playwright 和本地 Chrome 检查全程、导航、模式切换、季节、章节与响应式布局。`tests/capture.cjs` 使用 Playwright 和 Sharp 重建 WebP 配图。这些工具不属于网站运行依赖。

如果开发环境已经安装相应模块，可通过环境变量指定路径：

```sh
PLAYWRIGHT_PATH=/absolute/path/to/playwright \
CHROME_PATH=/absolute/path/to/chrome \
node tests/verify.cjs

PLAYWRIGHT_PATH=/absolute/path/to/playwright \
SHARP_PATH=/absolute/path/to/sharp \
CHROME_PATH=/absolute/path/to/chrome \
node tests/capture.cjs
```

验收结果写入 `tests/verification.json`；子路径测试可设置 `TEST_URL=http://127.0.0.1:4174/welldone/`。脚本默认路径对应本次开发环境，可用上述变量覆盖。

## 实现边界

这是受日式建筑启发的原创场景，不是历史城堡的精确复原；榫卯章节是简化构造示意。漫游相机沿预设路线进行，不提供 WASD 游戏式自由行走。自由观察模式采用轨道相机，没有通用物理碰撞系统。

冬季为局部地面积雪与落叶树枝；没有全屋顶积雪模拟。没有音频、表单、联网提交或任何后台服务。未承诺特定手机硬件上的帧率；窄屏浏览器验证不能替代真机 GPU 测试。

## 水彩茶室

直接访问 `/?room=tea`（子路径部署则 `/repository-name/?room=tea`）进入参考图构图。茶室采用暖纸墙面、蜂蜜色木桌、浅草色榻榻米、鼠尾草色坐垫、纸伞与前景木柱。茶室镜头局部降低为约 1.3 米的低视点，滚动漫游平滑经过该构图；其余路线保持原来的连续空间。

茶室改为带露天采光的空间，西侧原整片屋顶收为东侧回廊窄檐。桌案、陶器、坐垫与纸屏均为三维几何，自由观察仍可旋转与缩放。材质只在接近茶室或打开深链接时请求，并缓存后续加载；后处理现已推广到整座城堡与榫卯示意，使用实时渲染目标，不采样完整参考图。

参考图衍生材质的来源与授权边界记录在 `SOURCES.md`。视觉验收沿用 Dream Loop Pro 的独立截图比较，实际状态与限制见 `TESTING.md`。`tests/tea-room.cjs` 补充检查纹理懒加载、子路径、防黑屏、桌面/窄屏性能与返回视角。

## 全项目手绘统一（2026-11-18）

根据“先不精修茶室，整体改成同样手绘风格”的要求，已将纸感、颜料层次与暖色光照扩展到山路、石垣、木桥、城门、主殿、庭院、书斋、兵具间、楼梯和望楼。茶室的单场景精修保持暂停，本次不以逐像素复刻参考图为目标。

`js/paint.js` 集中管理十张共享采样（木材、灰泥、瓦色、石材、通用色洗、纸纹、树冠、水面、远山、云层）。这些开场可见表面先加载；茶室专用材质仍在接近时加载。网格使用世界坐标投射颜料，减少大墙面与地板的纹理拉伸；树冠与远山也采用同一套色层。窄屏启动时降低树冠几何密度。

材料章节将手绘表面采样叠合到构造纹理中，保留滚动停留、推进与过渡。榫卯示意使用共享木纹与纸感渲染；庭院四季和房间卡片已从新版场景重建。页面与平面图采用暖纸色、鼠尾草绿和淡赭色。

`tests/paint-tour.cjs` 捕获十个主要位置并记录桌面/窄屏帧率。测试与视觉记录见 `TESTING.md`；素材来源沿用 `SOURCES.md` 的用户附件授权边界。


## 城堡全景 · 三轮修改（2026-11-18）

以新提供的城堡水彩全景为目标，按 Dream Loop Pro 完成三轮实现、实际截图和独立评审，评分为 **6.60 → 6.95 → 7.30 / 10**。按用户指定三轮停止，尚未达到 8 分视觉标准。

开场镜头使用 `SETTINGS.panoramaFov`，随漫游平滑恢复正常视角。更新了树冠体块、暖灰白墙面、蓝灰瓦顶、错缝石垣、铺地、护城河反射、山体与透明云层色洗。`paint-palette.js` 按各材质采样的亮度分布校准颜料对比，避免统一增噪。所有建筑仍为可进入的三维几何，未使用整幅参考画替换场景。

`tests/panorama.cjs` 在独立的桌面与窄屏浏览器上下文检查懒加载、四季、旋转与返回，并记录帧率；具体报告见 `tests/panorama-verification.json`。三轮评审存于 `tests/panorama-verdict-*.md`。树冠分组、瓦线、石缝和水面倒影仍与参考存在差距，详见 `TESTING.md`。
