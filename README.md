# 薄霧城 · Usugiri Castle

一座虚构的日式山城。网页仅保留全屏 3D 场景与漫游控件，使用原生 HTML、CSS、JavaScript 与 Three.js：从山路、木桥、城门进入主殿，走过茶室、中庭、书斋与兵具间，沿两段木阶抵达望楼。

## 本地运行

在项目目录启动任意静态 HTTP 服务器，例如：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

打开 `http://127.0.0.1:4173/`。ES modules 必须通过 HTTP 加载，不能直接双击 `index.html`。运行网站不需要 Node、npm、打包器、后端或 API key。

## 操作

- 滚动：沿统一的连续相机路线前进、后退；地点按镜头所在区域更新，楼梯入口结合注视方向切换名称。
- 左下地点导航：点击具名地点跳转至木桥、茶室、中庭、望楼等区域；窄屏可横向滑动，当前地点自动跟随。
- 「自由观察」：保留当前镜头、房间与屋顶状态，原地拖动环视；滚轮或双指变焦。聚焦画布后可用方向键转向、加减键变焦。
- 「返回漫游」或 Escape：淡出恢复进入检查前的进度、相机、滚动书签与焦点；保留原有季节。
- 右上春、夏、秋、冬：更新植被、地面、环境光、粒子与薄雪，保持相机位置。
- 点击底部第一个地点标记：回到山路起点。漫游终点保持 3D 视图，不再进入其他页面。

网页已移除建筑介绍、材料近观、榫卯分解、庭院四季图文、房间卡片和页脚；顶部品牌栏、「入城」「城内案内」入口与地图弹窗也已移除；中庭与各房间仍可通过底部地点标记抵达。

## 空间与路线

一单位为一米。前庭地面标高为 4，主殿为 5.2，天守二层为 10.4，望楼为 15.6；主要步行视高为 1.65 米。开场位于较高的山路，沿坡下降到木桥。

主殿呈 U 形围绕露天中庭：西侧茶室、东侧书斋与兵具间、前侧回廊。天守在北侧。两段楼梯的楼板留有真实开口，楼梯平台与楼面连接。

`WAYPOINTS` 中的 `p` 是相机位置，`t` 是观察目标。带 `id` 的点供地点标记使用。`WalkRoute` 以弧长映射滚动进度，避免关键点间距不同造成速度骤变。新增房间时，应一起修改建筑与关键点。

## 渲染与资源

- 建筑与纹理分批构造，中途让出主线程；先编译并显示主要建筑，再完成外围植被。
- 静态几何按材质合并；重复石块与地板细缝使用实例化。
- 屋顶、季节植被和积雪保持独立，便于剖切与季节更新。
- 阴影缓存；只有季节与剖切变化时更新。远景使用分层山形与雾。
- 中庭池与护城河使用 256/512 像素平面反射；护城河叠加流动的水彩色层和轻微反射扰动。
- 页面只有一个主场景 renderer；标签页隐藏后停止绘制。材料近观和榫卯章节的初始化代码已移除。
- 默认像素比上限桌面 1.65、窄屏 1.3，可在 `SETTINGS` 中调整。
- 原图文章节的配图保留为历史资源，当前页面不加载这些图片。三维场景使用的手绘材质保持原有按需加载和缓存。
- 字体使用系统字体，无外部字体请求。全部运行依赖在 `vendor/`，上线后无需访问 CDN。
- 尊重 `prefers-reduced-motion`，停用环境运动并减少过渡。

## 验收与开发工具

`tests/verify.cjs` 使用 Playwright 和本地 Chrome 检查全程、导航、模式切换、季节、3D 终点及响应式布局。`tests/capture.cjs` 使用 Playwright 和 Sharp 重建 WebP 配图。这些工具不属于网站运行依赖。

如果开发环境已经安装相应模块，可通过环境变量指定路径：

```sh
PLAYWRIGHT_PATH=/absolute/path/to/playwright \
CHROME_PATH=/absolute/path/to/chrome \
node tests/verify.cjs

PLAYWRIGHT_PATH=/absolute/path/to/playwright \
SHARP_PATH=/absolute/path/to/sharp \
CHROME_PATH=/absolute/path/to/chrome \
node tests/capture.cjs
```

验收结果写入 `tests/verification.json`；子路径测试可设置 `TEST_URL=http://127.0.0.1:4174/welldone/`。脚本默认路径对应本次开发环境，可用上述变量覆盖。

## 实现边界

这是受日式建筑启发的原创场景，不是历史城堡的精确复原。漫游相机沿预设路线进行，不提供 WASD 游戏式自由行走。自由观察模式固定相机位置，只改变朝向和视场角；没有通用物理碰撞系统。

冬季为局部地面积雪与落叶树枝；没有全屋顶积雪模拟。没有音频、表单、联网提交或任何后台服务。未承诺特定手机硬件上的帧率；窄屏浏览器验证不能替代真机 GPU 测试。

## 水彩茶室

直接访问 `/?room=tea`（子路径部署则 `/repository-name/?room=tea`）进入参考图构图。茶室采用暖纸墙面、蜂蜜色木桌、浅草色榻榻米、鼠尾草色坐垫、纸伞与前景木柱。茶室镜头局部降低为约 1.3 米的低视点，滚动漫游平滑经过该构图；其余路线保持原来的连续空间。

茶室改为带露天采光的空间，西侧原整片屋顶收为东侧回廊窄檐。桌案、陶器、坐垫与纸屏均为三维几何，自由观察仍可旋转与缩放。材质只在接近茶室或打开深链接时请求，并缓存后续加载；后处理现已推广到整座城堡，使用实时渲染目标，不采样完整参考图。

参考图衍生材质的来源与授权边界记录在 `SOURCES.md`。视觉验收沿用 Dream Loop Pro 的独立截图比较，实际状态与限制见 `TESTING.md`。`tests/tea-room.cjs` 补充检查纹理懒加载、子路径、防黑屏、桌面/窄屏性能与返回视角。

### 全项目手绘统一（2026-11-18）

根据“先不精修茶室，整体改成同样手绘风格”的要求，已将纸感、颜料层次与暖色光照扩展到山路、石垣、木桥、城门、主殿、庭院、书斋、兵具间、楼梯和望楼。茶室的单场景精修保持暂停，本次不以逐像素复刻参考图为目标。

`js/paint.js` 集中管理共享表面采样（木材、树皮、灰泥、瓦色、石材、通用色洗、地板、草地、纸纹、树冠、水面、远山、云层）。这些开场可见表面先加载；茶室专用材质仍在接近时加载。网格使用世界坐标投射颜料，减少大墙面与地板的纹理拉伸；树冠与远山也采用同一套色层。窄屏启动时降低树冠几何密度。

材料章节将手绘表面采样叠合到构造纹理中，保留滚动停留、推进与过渡。榫卯示意使用共享木纹与纸感渲染；庭院四季和房间卡片已从新版场景重建。页面与平面图采用暖纸色、鼠尾草绿和淡赭色。

`tests/paint-tour.cjs` 捕获十个主要位置并记录桌面/窄屏帧率。测试与视觉记录见 `TESTING.md`；素材来源沿用 `SOURCES.md` 的用户附件授权边界。
